# Diagram-fence рендерится с mermaid `securityLevel: 'strict'`; сгенерированный SVG потребляется как доверенный вывод генератора

[English](0001-diagram-fence-trust-model.md) | 中文

Исходник diagram-fence — это текст, написанный моделью: произвольный вывод модели, а не пользовательский конфигурируемый контент. Поэтому мы сохраняем дефолтный `strict` уровень безопасности mermaid: HTML-label санитизируются, а click-действия, написанные внутри исходника диаграммы (`click Node href/callback`), никогда не исполняются. Единственная интерактивность, которую предлагает fence, — слой viewer (зум, пан, сброс, разворот в модалку, копирование исходника), и его элементы управления принадлежат читателю, а не диаграмме. SVG, который mermaid генерирует под `strict`, потребляется через `innerHTML` — тот же принцип доверия, что уже применён к span-деревьям shiki в CodeBlock и выводу KaTeX: статический вывод доверенного генератора, а не сырой HTML модели.

## Рассмотренные варианты

- `securityLevel: 'loose'` — включает click-цели из исходника, но отключает санитизацию label на произвольном выводе модели; отклонено для v1. Вернуться только за санитайзером, whitelisting-ящим `http(s)`-href, извлечённые из исходника.
- Извлекать href самим под `strict` — сохраняет санитизацию, но добавляет самописный слой парсинга и обработчиков; отложено как выходящее за рамки v1 с интерактивностью только viewer.

## Последствия

- Диаграммы, полагающиеся на HTML-label или click-действия из исходника, рендерятся инертно/санитизированно; диаграмма остаётся на месте — теряются только интеракции.
- Любой будущий переход к click-действиям из исходника должен сначала изменить этот ADR: пересматривается граница доверия, а не фича-флаг.
