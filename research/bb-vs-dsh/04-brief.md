**«bb — основной инструмент»** (форма 2 из четырёх разрешённых). Взвешенная сумма: bb 4.50 против 3.11 у dsh; разрыв 1.39 ≥ 0.3 — паритета нет (R3), тай-брейки R4 не потребовались. ## 3. Разбор оси 1: отдельные страницы и дашборды

**bb.** Отдельная страница — штатный механизм: `navPanel` даёт плагину собственный пункт сайдбара и весь маршрут `/plugins/<pluginId>/<path>/*` с fixedTabs и deep links; хост оборачивает её в общий App panel, владея сплитами и вкладками (BB-11, BB-12; [03] bb-1). Из коробки: панель Automations с историей запусков (BB-7); страницы Settings: General, Keyboard, Updates, Machines (карточка машины с лимитом разрешений), Providers, Memory, Skills, Remote access и другие (BB-5, BB-8–BB-11, BB-17); магазин Extensions → Plugins → Browse; 21 builtin-плагин поставляет часть панелей (BB-15; число — по [03] №1); слот `homepageSection` на корневом экране compose (BB-11, BB-12). Дашборд-подобные агрегаты: Updates с бейджем сайдбара, страница машины, `bb automation runs`, `bb thread count --by` (BB-3, BB-5, BB-7) и облачный дашборд getbb.app (BB-8). Единой страницы-дашборда нет; её сборка — класс S/M (`navPanel` + useRpc/useRealtime, BB-11, BB-12).

**dsh.** Оболочка — сетка sidebar | conversation | details плюс `shell.overlay`, отрисованная из единственного слота `root`; роутера нет (DSH-2, DSH-4). Сгенерированный каталог слотов исчерпываем (48 ключей): «страница», «route», «dashboard» отсутствуют; `react-router` и History API в src клиента нулевые (DSH-3; [03] dsh-1). Вне потока сообщений живут: браузер воркспейсов и сессий в сайдбаре (группировка, контентный поиск, fork/archive, алармы) (DSH-5, DSH-7, DSH-16); настройки — fixed-position панель-потомок колонки с секциями General/Models/Plugins (DSH-6, DSH-8); Jobs и Schedule — поповеры в шапке сессии (DSH-14, DSH-15); frame-wide панель ui-cordis из футера сайдбара (DSH-9). Навигационного элемента первого класса на не-чатовый экран нет; агрегированного обзора задач и машин нет — jobs привязаны к сессии, сущности «машина» нет (DSH-15, DSH-18); секция настроек открывается программно (`openSection(id)`), но без URL ([03], новые факты №2).

**Разрыв и закрытие средствами dsh.** Из определения дашборда [01] dsh закрывает лишь «доступен без открытого треда» и только для списка сессий; «отдельный экран с агрегированным состоянием задач, машин, событий» сегодня нулевой (DSH-15, DSH-18). Путь M: плагин с `dsh.client` регистрируется в `shell.overlay` — каталог прямо направляет whole-app-поверхности туда (slot-catalog.ts:1373), прецедент — панель ui-cordis (DSH-9, DSH-10; [03], новые факты №1). Но у такой поверхности нет ни пункта сайдбара, ни маршрута, ни deep link — только кнопка, которую плагин сам ставит в `sidebar.footer.action` (DSH-5). Отдельная страница в смысле must-have требует правки оболочки — класс L (DSH-4, DSH-11). Поэтому R2 не спасает форму 3 для dsh: S/M даёт лишь дашборд-оверлей, не «отдельную страницу».

## 4. Существенные различия по остальным осям

**Ось 3 (5 против 4).** Plugin SDK bb полного доверия добавляет страницы, заменяет список тредов, навигацию сайдбара и рендереры; всё-есть-плагин подтверждён builtin-списком (BB-11–BB-15). dsh: типовая алгебра слотов с каталогом для модели (`cordis_inspect`), динамические пакеты из чата (DSH-9–DSH-11); MCP-клиент даёт инструменты как нативные `mcp__<server>__<tool>` (mcp/README.md:2–3 через [02] «Пересечения»); в `bb guide` MCP не упомянут — пробел документации, не доказательство отсутствия ([02], «Тонкие места» №3). Асимметрия: плагин bb создаёт страницу, плагин dsh занимает объявленные слоты (DSH-3, DSH-10).

**Ось 4 (5 против 3).** bb automations: cron с таймзоной, разовые и интервальные запуски, промпт или скрипт без модели, история и панель; workflows-плагин — durable-оркестрация (BB-7, BB-11). dsh: schedule — напоминания одной сессии, доставка отложенным ходом (DSH-14); workflow-сьема — скрипты с подагентами на worker-thread движке; `ctx.jobs` виден только в шапке открытой сессии (DSH-15, DSH-17). Закрытие разрыва dsh: cron-планировщик — новый плагин класса M.

**Ось 5 (4 против 5).** Ядро dsh документировано первично: agent-loop с waterfall-точками, compaction, plan/todo/subagent/guard, permission, пресеты (DSH-1). Факты bb косвенны — `--plan` с approve/deny, `bb thread compact`, подагенты и ретраи провайдера: первичного документа о встроенных инструментах агента нет, отсюда 4 с этой оговоркой (BB-3, BB-10, BB-11; [02], «Тонкие места» №1).

**Ось 8 (5 против 2).** bb connect: туннель `<handle>.getbb.app`, шаринг портов ссылками, мобильное приложение, облачный дашборд (BB-8). dsh: локальный HTTP (DSH-13; «serves browsers only» — webserver/README.md:12 по [03] №3), webhook и ACP/SDK (DSH-17); «tunnel» в исходниках — transport воркера и пользовательский reverse-proxy, не фича ([03], dsh-6b). Закрытие для dsh: LAN через `0.0.0.0` — класс S (конфигурация); публичный туннель — новый плагин M–L, готового пути нет.

## 5. Риски и условия пересмотра (R6)

База: UI не запускался визуально ни у одного инструмента — факты из первичных текстов (справочник bb; код, доки и каталог dsh с гейтом `verify-client-catalog`) ([02], «Ограничения поиска»; [03]); ось 5 по bb тонка; отрицательные факты dsh — греп на одном коммите `d6d62f6dce`, усиленный исчерпываемым каталогом слотов и нулём History API (DSH-18; [03] dsh-1). Условия пересмотра: (1) дашборд в `shell.overlay` (M) собран и на практике закрывает вне-чатовый обзор — сдвиг к форме 3 или 1; (2) потребность в дашбордах окажется эпизодической — предпосылка веса 30% слабеет, сдвиг к dsh; (3) в оболочке dsh появится слот страницы/маршрута или навигация сайдбара (L) — must-have закрыт структурно, сдвиг к форме 1/3; (4) данные тредов недостижимы из Plugin SDK bb для единого дашборда — ось 1 bb слабеет, сдвиг к dsh; (5) визуальный запуск противоречит инвентарю любой стороны — пересчёт матрицы.

## 6. Рекомендованный режим работы и первые шаги

Режим: bb — основной с первой недели; dsh не удалять и не дорабатывать до пересмотра по разделу 5. Первая неделя на bb: (1) настроить Settings → Appearance → Sidebar/Navigation под свой список тредов (BB-9, BB-13); (2) `bb plugin new` даёт скелет со страницей в сайдбаре — собрать страницу-дашборд `navPanel` на useRpc/useRealtime: машины, Updates, automation runs, thread count (BB-11, BB-12, BB-5, BB-7); (3) перевести повторяющиеся задачи в automations с cron и таймзоной (BB-7); (4) включить connect для доступа с телефона (BB-8); (5) завести секции тредов под текущие воркспейсы dsh (BB-3; DSH-16).
